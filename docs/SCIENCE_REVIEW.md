# Science Review — MIZAN + BATYR AGA + Ghost Busters audit

> Generated by `scripts/science_review.py` from the raw NASA files. Numbers are recomputed on every run; machine-readable copy in `docs/data/science_review.json`. Do not edit by hand.

## What this review is, and what it is not

- It is a **self-audit**: the same AI system that wrote the engines wrote the checks below. Under the team's MIZAN rules that is **not independent scientific validation**, and no status is raised because of it. Every evidence record stays `OBSERVED` or `HYPOTHESIS`.
- An earlier verification pass by another session of the same model is likewise **not independent**.
- Gemini's report is an independent *computation* of sixteen numbers. Where our numbers agree with it, those single values are marked as replicated. Gemini's interpretations are not adopted, and nothing in the engines was tuned to match it (`docs/GEMINI_REPRODUCTION.md`).
- **Human scientific review: NOT DONE.** It is the first item under *Open items*.

Case audited: Pavlodar grid cell (52.29 N, 76.97 E), 2001–2024, NASA POWER monthly data (MERRA-2).

## 1. Spurious correlation from seasonality

Two variables that both follow the calendar correlate strongly even if their year-to-year departures are unrelated. The engine therefore reports four numbers per pair and decides on the last one.

| Pair | Raw | Seasonal cycles alone | Deseasonalized | Detrended | Spearman (deseas.) | Month-standardized |
|---|---|---|---|---|---|---|
| T2M-PRECTOTCORR | +0.439 | +0.860 | -0.125 | -0.121 | -0.158 | -0.185 |
| T2M-RH2M | -0.945 | -0.976 | -0.316 | -0.316 | -0.353 | -0.415 |
| T2M-QV2M | +0.950 | +0.967 | +0.531 | +0.549 | +0.658 | +0.674 |
| PRECTOTCORR-RH2M | -0.285 | -0.775 | +0.593 | +0.590 | +0.534 | +0.367 |
| PRECTOTCORR-QV2M | +0.551 | +0.936 | +0.308 | +0.295 | +0.255 | +0.224 |
| RH2M-QV2M | -0.844 | -0.912 | +0.388 | +0.358 | +0.266 | +0.174 |

- **Precipitation–humidity:** raw -0.285, but the two seasonal cycles alone give -0.775: the negative raw value is the calendar (humid winters with little precipitation, drier-air summers with more). With the calendar removed the sign reverses to +0.593.
- **Temperature–humidity:** raw -0.945 is almost entirely the seasonal cycle (-0.976); the anomaly association is -0.316.
- **Temperature–precipitation:** raw +0.439 becomes -0.125; the sign differs between seasons (DJF +0.37, MAM -0.34, JJA -0.32, SON -0.35), so the all-year number hides opposite behaviour.
- **Robustness of the removal.** Rank correlation (Spearman) gives the same signs and similar sizes, so outliers are not responsible. A climatology taken from only one half of the record changes the deseasonalized precipitation–humidity value from +0.593 to +0.588 (the two halves give the same number by symmetry).
- **Finding: the pooled value is weighted towards the warm season.** When each calendar month's anomalies are divided by that month's own standard deviation, so that every month counts equally, precipitation–humidity falls from +0.593 to +0.367. The sign is unchanged, but the all-year number is carried by months with large precipitation variance. By season: DJF -0.06, MAM +0.54, JJA +0.70, SON +0.64. The association is a spring-to-autumn feature and is absent in winter; the demo and the submission text say so.
- **Residual risk.** A fixed monthly climatology does not remove a seasonal cycle whose shape changes over the record; by-season results are reported for that reason.

## 2. Significance and false-discovery control

One default investigation runs 3 annual trend tests, 12 seasonal trend tests, 3 pair tests and 39 lag tests. Benjamini–Hochberg is applied inside each family.

| Variable | Theil–Sen slope | 95% CI | Mann–Kendall p | Reported p | q | Verdict |
|---|---|---|---|---|---|---|
| T2M | -0.021 °C/year | -0.067 to +0.046 | 0.413 | 0.578 | 0.578 | NO_SIGNIFICANT_TREND_DETECTED |
| RH2M | +0.164 percentage points/year | +0.007 to +0.293 | 0.035 | 0.035 | 0.105 | FRAGILE_TREND |
| PRECTOTCORR | +0.005 mm/day per year | -0.004 to +0.015 | 0.264 | 0.264 | 0.397 | NO_SIGNIFICANT_TREND_DETECTED |

- The only nominally significant trend is relative humidity (Mann–Kendall p = 0.035). After false-discovery control q = 0.105, and leaving out any one of the years 2002, 2008, 2017, 2018, 2024 changes whether it is significant. It is reported as `FRAGILE_TREND`, not as a trend.
- For temperature and precipitation the result is *no significant trend detected*, which is not a finding of stability: the confidence intervals include change in either direction.

| Pair | Detrended r | 95% CI | n | Effective n | Naive p | Adjusted p | Year-shuffle p | q across pairs | Status |
|---|---|---|---|---|---|---|---|---|---|
| T2M-PRECTOTCORR | -0.121 | -0.23 to -0.00 | 288 | 283 | 0.040 | 0.042 | 0.011 | 0.042 | WEAK |
| T2M-RH2M | -0.316 | -0.42 to -0.20 | 288 | 252 | < 0.001 | < 0.001 | < 0.001 | < 0.001 | SUPPORTED |
| PRECTOTCORR-RH2M | +0.590 | +0.51 to +0.66 | 288 | 278 | < 0.001 | < 0.001 | < 0.001 | < 0.001 | SUPPORTED |

- **Gap found and closed:** pair tests were not corrected across pairs. `q across pairs` is now computed and shown; with three pairs and with six pairs (specific humidity added) no status changes.
- The temperature–precipitation association (r = -0.121, upper confidence bound -0.004) is statistically detectable and practically negligible; it is labelled `WEAK`.
- Lag scans, non-zero lags passing an uncorrected test → still significant after correction: T2M-PRECTOTCORR 2 → 0; T2M-RH2M 2 → 1; PRECTOTCORR-RH2M 5 → 3.
- Thresholds (α = 0.05, |r| ≥ 0.2 for `SUPPORTED`) were fixed in code before the Pavlodar numbers were looked at and are the same for every region.

## 3. Autocorrelation

- **Monthly anomalies.** Lag-1 autocorrelation of the detrended anomalies: T2M +0.18, PRECTOTCORR +0.05, RH2M +0.37. Effective sample sizes are 283, 252, 278 of 288 months for the three pairs. The year-block permutation control, which keeps each variable's within-year structure intact, agrees with the adjusted p-values.
- **Annual means.** Lag-1 autocorrelation: T2M +0.09, RH2M +0.07, PRECTOTCORR +0.08. The reported trend p is the larger of the Hamed–Rao modified Mann–Kendall p and the AR(1)-adjusted least-squares p.
- **Known weakness, measured.** SYNTHETIC control, 2000 trend-free AR(1) series of 24 years per row; share rejected at the 5% level (should be 5%):

| Lag-1 autocorrelation of the noise | Classic Mann–Kendall | Reported rule |
|---|---|---|
| 0.0 | 4.0% | 2.9% |
| 0.3 | 11.0% | 7.0% |
| 0.6 | 28.5% | 12.6% |

  The reported rule is better than the classic test but still rejects too often when persistence is strong. With 24 annual values the autocorrelation itself is poorly estimated, which no correction fully repairs. This is why a significant p alone never yields `ROBUST_TREND`: the window and leave-one-out checks must also pass.

## 5. Correlation versus causation

- Every published sentence passes the MIZAN Guard (`guard.py`), which rejects causal verbs, proof language, "no change" conclusions from a non-significant test, and reading a lag as a direction of influence, in English and Russian. The test suite includes adversarial sentences.
- Physical explanations exist only as records with status `HYPOTHESIS`, verdict `UNTESTED`, each with a proposed test. They annotate graph edges and never create one.
- New in this review: **partial correlations** of detrended anomalies with four variables in play. They show whether an association remains when another series is held fixed statistically; they are still correlations and assume linear relations.

## 6. RH2M is a computed variable tied to temperature

Relative humidity is the ratio of the water vapour present to the amount the air could hold at its temperature. NASA POWER's methodology page states that its relative humidity is calculated from MERRA-2 pressure, temperature and specific humidity, over water only ([POWER: Relative Humidity](https://power.larc.nasa.gov/docs/methodology/meteorology/relative-humidity/)). Before this review the temperature–humidity edge was presented like any other association.

**Check (nothing fitted).** Relative humidity was rebuilt from monthly T2M and QV2M with the Magnus formula at a constant standard-atmosphere pressure of 1000.0 hPa for the grid cell's elevation, and compared with the RH2M values in the NASA file:

- raw series: r = +0.982, mean absolute difference 2.60 percentage points (bias -0.59);
- detrended anomalies: r = +0.767;
- share of the variance of relative-humidity anomalies reproduced by a linear combination of temperature and specific-humidity anomalies: 50% over all months; by season DJF 19%, MAM 87%, JJA 98%, SON 69%.

**Reading.**

- In summer relative humidity carries almost no information beyond temperature and moisture content (98%). The low winter figure (19%) does **not** show independent information: the check works on monthly means with a constant pressure and a *linear* fit, while the true relation is strongly non-linear at low temperatures (mean absolute difference of the reconstruction in winter 4.9 percentage points against 2.0 in summer). Which of these accounts for the winter mismatch was not tested.
- Warmer-than-usual months hold **more** water vapour (temperature–specific humidity +0.549) and yet have **lower** relative humidity (-0.316); with moisture content held fixed the temperature–relative humidity value strengthens to -0.657. That is what the definition of relative humidity predicts, so the temperature–humidity edge is **partly an identity, not a discovery**.
- Consequences in the product: the edge carries a ⚙ *built-in dependence* flag in the graph, the pair card and the evidence record; the episode timeline lists it as a counterexample; *What these data cannot tell us* states it; a `DERIVED_VARIABLE_CONFIRMED` evidence record holds the numbers above.
- The proposed explanation of the temperature–humidity association stays a `HYPOTHESIS`. The check above is consistent with it and does not prove it.

- Source: NASA POWER Monthly and Annual API v2.10.0 (`power.larc.nasa.gov`), community AG. The response headers name MERRA-2 as the source. These are **model reanalysis values for one grid cell of about 0.5° × 0.625°**, not station measurements.
- Chain of custody: the build sandbox had no route to NASA, so each response was fetched in the team's Chrome browser, its SHA-256 was computed in the browser on the response body, the body was stored in `data/raw/` and re-hashed. `scripts/build_provenance.py` fails if any byte differs. The engine re-verifies the hash every time a file is read.
- The API's own annual values (`YYYY13` keys) are kept apart from the twelve months and are reproduced by our day-weighted means to within rounding.
- **Live path NOT RUN.** The code path in which the backend itself calls NASA (`PowerStore._fetch_live`) is covered only by tests with a stubbed HTTP transport (`test_08_live_path.py`): they show what the backend does with a good answer, an HTTP error, a network failure and a malformed or mismatched body, not that the real service answers. It has not been exercised against NASA from the build environment.
- **GPM IMERG.** The POWER service accepts the parameter `IMERG_PRECTOT`, but for this point it returned the missing-value code (−999) for all 288 months and all 24 annual keys, and its header lists MERRA-2 as the only source. The file is stored as evidence of that; the engine refuses to analyse the variable (HTTP 422, no numbers). An independent satellite check of precipitation is therefore **NOT AVAILABLE** by this route. NASA Giovanni / GES DISC was **NOT RUN**: access from the build environment was not permitted.
- Consequence: all four variables come from one model. Relationships between them may be tighter than in nature, and none has been confirmed against independent observations.
